# 安全加固记录（2026-11-13）

本轮只做"堵窟窿"，没有改业务逻辑。四项改动：

## 1. 所有接口要求访问令牌

- 新增 `backend/app/auth.py`，提供 `require_auth` 依赖，挂在
  `/api/import-batches` 与 `/api/review-tasks` 两个路由上。
- 令牌读取顺序：`X-API-Token` 请求头 → `Authorization: Bearer <token>`。
- 令牌来自环境变量 `APP_AUTH_TOKEN`（写在 `backend/.env`）：

  ```bash
  python -c "import secrets; print(secrets.token_urlsafe(32))"
  ```

  把生成结果写进 `backend/.env` 的 `APP_AUTH_TOKEN=`，再把同一个值写进
  `frontend/.env.local` 的 `NEXT_PUBLIC_API_TOKEN=`。

- **未配置令牌时不是"全放开"**，而是只允许本机回环地址访问：开发环境零配置
  照常可用，服务一旦被内网访问就会返回 403 并提示去配置令牌。
- 前端 `src/lib/api.ts` 会自动带上令牌；`<audio>` 与下载链接两种发不出请求头
  的场景单独处理（见下）。

## 2. 录音不再通过公开静态目录暴露

- 删除了 `main.py` 里的 `app.mount("/storage", StaticFiles(...))`。
- 新增 `backend/app/api/recordings.py`：`GET /api/recordings/{id}/stream`，
  按记录 ID 取文件，校验路径不会逃逸出 `backend/` 目录，返回 `FileResponse`
  （支持 Range 请求，进度条拖动照常可用）。
- 该接口额外接受 `?token=`，因为 `<audio src>` 无法自定义请求头——这是唯一
  允许令牌出现在 URL 中的地方。
- 前端审核详情页的导出按钮从 `<a href>` 改成 `downloadFile()`（fetch + blob），
  否则浏览器发不出令牌头会拿到 401。

## 3. CSV 导出防公式注入

- 新增 `backend/app/security.py::csv_safe_cell`，在写 CSV 前统一转义。
- 规则：以 `=`、`+`、`-`、`@`、制表符、回车、换行开头的单元格加前导单引号，
  破坏 Excel 的公式求值；**纯数字**（含 `-12.5%`、`+8`）保持原样，避免导出的
  金额/占比退化成文本。

## 4. 上传体积后端兜底

- `import_service.save_upload()` 改为分块落盘并统计字节数，超过上限直接
  抛 413 并删除半截文件。
- 上限集中在 `app/security.py`：Excel 50 MB、录音 100 MB，与前端常量一致。

```bash
cd backend
python -m app.security          # 纯函数自检，不需要装任何依赖
pytest -q                       # 新增 3 个测试文件
```

新增用例：

| 文件 | 覆盖内容 |
| --- | --- |
| `tests/test_security.py` | 29 个参数化用例：公式前缀转义、负数保持不变、回环地址判定 |
| `tests/test_auth.py` | 无令牌 401 / 错令牌 401 / 正确头与 Bearer 放行 / 未配置令牌时非本机 403 / 录音接口 `?token=` / `/storage` 已不可访问 |

`tests/conftest.py` 加了一个 autouse fixture，让原有 19 个用例不受鉴权影响；
鉴权本身由 `test_auth.py` 单独验证。
