# 转写准确率优化（2026-11-14）

本轮只改转写环节，不动字段提取和业务逻辑。四项改动，风险从低到高排列；每一项都能单独回滚。

## 改了什么

### 1. 加 `prompt` 热词表（收益最大）

**之前**：调用 `audio.transcriptions.create` 时没传 `prompt`，模型对"马爹利 / 轩尼诗 / 蓝带 / 堆头"这类专有名词只能靠猜。错一个字——"马爹利"转成"马爹丽"——后续字段匹配就整条失败，且失败原因看不出来。

**现在**：`prompts/transcription_prompt.md` 作为基础提示词，再自动拼上**本次门店名和业务员姓名**（来自导入的 Excel），一起发给模型。

- 改这个文件不需要改代码、不需要重启服务（按 mtime 自动重载）
- 以 `#` 开头的行是注释，不会发给模型
- 总长上限 800 字符，超长从末尾截断
- 文件缺失或只有注释时退回内置默认提示词，不会让分析失败

自检：

```bash
cd backend
python -m app.transcription_prompt    # 打印模型实际收到的 prompt 和长度
```

### 2. 转写前音频规范化

**之前**：≤25MB 的录音**原文件直接上传**，不做任何处理。门店录音的典型问题是手机揣在兜里、远场、电平极低（实测样例 mean_volume -52 dB）。

**现在**：所有录音先过一遍 ffmpeg：

```
ffmpeg -i in.m4a -map 0:a:0 -ac 1 -ar 16000 \
  -af "highpass=f=80,loudnorm=I=-16:TP=-1.5:LRA=11" -c:a flac out.flac
```

- `loudnorm`（EBU R128，-16 LUFS）是这一步的核心：实测样例从 -52 dB 提到 -18 dB
- `highpass=80` 去掉手机摩擦低频，不碰语音共振峰
- **不做降噪**。降噪会削辅音，背景有音乐时反而更差；要开必须单独 A/B
- 输出 16kHz 单声道 **FLAC**，避免对已有损文件做第二次有损编码
- `-map 0:a:0` 明确取第一路音频：手机录音常带封面图（video 流），不显式指定可能取错流
- 超过 25MB 时自动降级为 48k AAC 再试一次，仍超才切片
- **任何环节失败都回退到原始文件**，不会让一条录音变得不可转写

开关与滤镜链可配：`OPENAI_AUDIO_NORMALIZE`、`OPENAI_AUDIO_FILTERS`。

### 3. 切片改无损

**之前**：切片输出 64k AAC，对已经是有损源的音频再压一次，纯损失。

**现在**：切片输出 FLAC（输入已是 16kHz 单声道，无损且体积相当），并补了 `-nostdin`。

### 4. 幻觉片段过滤

`gpt-4o-transcribe` 在长静音段和纯音乐段会**凭空生成文字**，典型是"谢谢观看""字幕由 XX 提供"。这些假片段在这套系统里危害特别大——每个字段值都要求"原文逐字支持"，一段假原文足以伪造出假证据。

过滤规则（`app/transcript_quality.py`）：

| 规则 | 说明 |
|---|---|
| 词表命中 | `prompts/hallucination_phrases.txt`，去标点空格后子串匹配 |
| 无实义字符 | 只有标点/emoji 的片段 |
| 时长异常 | < 0.3 秒却带 20+ 字，真实语音不可能 |
| 重复长句 | 12 字以上完全相同的句子只保留前 2 次 |

**刻意保守**：短重复词（"好的""对"）全部保留，正常对话绝不误杀。漏掉一条假片段的代价只是提取时匹配不上；错杀一条真片段则信息永久丢失。

词表同样改文件即生效。自检：

```bash
cd backend
python -m app.transcript_quality
```

## 接口变化（注意）

`AnalysisProvider.transcribe(audio_path)` → `transcribe(audio_path, hotwords="")`。

参数有默认值，所以旧调用不会报错；但**任何自定义的 provider 替身/实现都要接受这个参数**，否则 `analyze_task` 调用时会 `TypeError`。仓库内三处测试替身已同步。

- `python -m app.transcript_quality`：11 个过滤场景全部符合预期

## 下一步该测什么

改完不等于变好，得能量化。建议按顺序：

1. **建基线（半天，最值得先做）**
   抽 20~30 条有代表性的录音（嘈杂的、方言重的、长录音各若干）人工标注，算 CER（中文用字错率，不是 WER）+ 数字准确率 + 品牌名召回率。没有这个集，后面所有改动都无法判断是否有效。

2. **顺手可得的代理指标**
   统计 `evidence_supports_value`（`app/field_rules.py:206`）返回 False 的比例——即"AI 说了值但原文找不到支撑"的比率。这个函数已经在跑，只是没人统计。改代码前后各拉一次，就能看出效果。

3. **分层归因"缺失字段"**
   抽 50 条缺失字段听 30 秒，分成三类：音频里有但转写没有（ASR 问题）／音频里也没有（业务员漏问，该改话术）／转写有但没提取（提取问题）。如果第二类占大头，那继续调 ASR 是错方向。

4. **回滚开关**
   出问题先关 `OPENAI_AUDIO_NORMALIZE=false`，即可退回旧的上传行为。
